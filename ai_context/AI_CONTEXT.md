# Contexto para IA - Almacen de Componentes

Este repositorio documenta materiales disponibles para proyectos de robotica, sistemas embebidos, IoT, automatizacion, cosplay electronico y recuperacion de drones.

## Objetivo operativo

Mantener un inventario tecnico que pueda ser entendido por una IA sin revisar el historial completo del chat. Cada componente debe indicar:

- nombre comun;
- categoria;
- cantidad;
- modelo o numero marcado;
- voltaje de trabajo;
- corriente o potencia;
- protocolo o tipo de senal;
- pines importantes;
- restricciones;
- estado de validacion;
- proyectos compatibles.

## Estado del usuario

El usuario esta construyendo una base de materiales para proyectos de robotica, embebidos, IoT y automatizacion. La prioridad no es comprar mas componentes, sino organizar el inventario, validar alimentacion y crear bancos de prueba seguros.

## Fase 1 registrada

Incluye Arduino Nano ATmega328P, ESP32-C3 Super Mini, ESP32 ESP-WROOM-32, NRF24L01, NRF24L01 PA LNA, servos SG90, motores DC 5 V, sensores DHT, bateria sellada 12 V, teclado numerico, AVR ISP Shield, Keyes L298, PCA9685, KY-037, HC-SR501, modulos TP4056 USB-C, touch HW-139, boost LM2587S, AHT10, MPU-6050, modulo vibrador, TFT SPI 1.8 y LED infrarrojo 850 nm.

## Fase 2 registrada

Incluye tarjetas recuperadas de drones YD-W6833-v.1c y HY-2016R a, controles de dron, un dron moderno con camara y motores de 2 cables, y baterias LiPo 952540 de 3.7 V.

## Regla principal de seguridad

No energizar placas recuperadas ni baterias sin validar polaridad, tension real y consumo. Los GPIO no alimentan motores, servos ni LEDs de potencia.

## Prioridades de proyecto

1. Base de alimentacion segura.
2. Calibrador de servos para evitar recorridos invertidos o sobreesfuerzo.
3. Nodo ambiental IoT.
4. Comunicacion NRF24L01.
5. Banco de motores DC.
6. Investigacion de drones recuperados.

## Criterio de datos

Los datos confirmados por el usuario se registran como confirmados. Los datos extraidos de PDFs o publicaciones de compra se marcan como referencia. Los datos no medidos fisicamente quedan como pendientes de validacion.
